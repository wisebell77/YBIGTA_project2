# 통합 — 세 분석을 하나의 프로젝트로

각자 독립적으로 수행한 세 분석을 **하나의 의사결정 깔때기**로 잇는다.
각자의 코드·설계는 그대로 둔다 — 설계가 다른 것은 약점이 아니라 삼각측량이다.

| 단계 | 질문 | 담당 | 핵심 답 |
|---|---|---|---|
| ① 상류 | 판촉이 수요를 만드는가? | 장준한 | 만든다 (구매확률 +24.3%, 총수량 +34.4%). 56일 payback 없음. 단 가치-매출 갭 13.4%p |
| ② 배분 | 어디에·누구에게·어떻게 줄 것인가? | 남궁현종 | 카테고리 확대 19/축소 25, 고객 Q1 낭비/Q5 수익, 1면·진열 병행, 지표는 가구 관점으로 |
| ③ 하류 | 판촉 이후 고객관계는? | 전영찬 | 체험은 만들지만 정상가 정착 약함(−5.5%p), 고객 반응형 5종별 CRM |

**관통 서사 (세 사람이 독립적으로 도달)**: 순진한 지표로 재면 결론이 뒤집힌다.
남궁현종 "부호 반전 4종" · 장준한 "보정 전후 소멸/반전 표" · 전영찬 "실현할인 −9.4% vs 전단지 +7.8%".

**상호 재현**: 서로 모르고 돌린 수치가 일치 — 당일 수량 +26.8/+27.5%, 56일 잠식 −0.031/−0.031,
부호 반전 +7.8/+7.9%.

## 자체 재현 파이프라인 — [`pipeline/`](pipeline/)

**이 폴더 하나로 전체 분석이 재현된다.** `data/` 원본 CSV만 있으면 BigQuery 없이
표준 처치 정의([처치정의_표준.md](처치정의_표준.md))로 세 사람의 분석을 전부 다시 계산한다.

```bash
python 통합/pipeline/run_all.py
```

각 스테이지는 legacy 모드로 원 분석 공표치를 먼저 재현해 구현의 정확성을 증명한 뒤
(72개 판정 불일치 0건, 딥할인 당일 효과 소수점 3자리 일치, ITT ±2% 이내 등 —
상세는 [pipeline/README.md](pipeline/README.md)), 표준 정의 결과를 `outputs/` 에 산출한다.
개인 폴더는 각자의 원 설계 아카이브로 보존된다.

## 개인 결과 결합판 (대조용 — `build_integration.py`)

### 01_category_triangulation.csv — 카테고리 삼각측량

우리 72개 카테고리 판정(전단지 ITT, 당일 순수취액 + halo)에 전영찬의
**딥할인 후 28일 매장 방문·전체 지출 변화**(하류 관계 축)를 결합. 71/72 매칭.

두 축은 같은 지표의 재측정이 아니라 **단기 수익 × 장기 관계**의 서로 다른 차원이다.
전영찬 축의 개별 유의성은 71개 중 6개뿐 — 장준한의 "FDR 후 robust 0/83"과 정합하며,
따라서 하류 축은 확정 증거가 아니라 **방향 참고 + 유의 시 가중**으로만 쓴다.

### 02_decision_matrix.csv — 최종 의사결정 매트릭스

규칙 기반(코드에 고정) 액션 배정. 신뢰도 '상' = 두 설계가 같은 방향 = **16개**:

- **확대 최우선 7**: CANDY-PACKAGED · SEAFOOD-FROZEN · DELI MEATS · FROZEN PIZZA · COOKIES/CONES · BAKED SWEET GOODS · BAG SNACKS
- **축소 최우선 9**: GRAPES · MELONS · SALAD MIX · TROPICAL FRUIT · BROCCOLI/CAULIFLOWER · MUSHROOMS · VEGETABLES-ALL OTHERS · REFRGRATD DOUGH · REFRGRATD JUICES/DRNKS

통합이 만든 새 뉘앙스 (개별 분석에는 없던 것):

- **BEEF**: 당일 순수취 1위(+$1.67)인데 28일 관계는 약화(Q4) → "확대하되 온보딩 설계"
- **GRAPES**: 당일 −$1.07 + 28일 매장지출 **−$13.6 (유의, 71개 중 6개뿐인 유의 신호)** → 축소 근거 3중 확인
- **ONIONS**: 당일 축소 판정이지만 halo(+$6.1, t=2.05)와 28일 관계(Q1) 모두 양호 → 유일하게 "축소 보류 — 실험"이 정당한 농산물

### 03_household_axis_crosstab.csv — 고객 축은 사실상 하나다

할인의존도(남궁현종: 로열티 할인액/정가 구매액, DAY≤547) × 할인친화도(전영찬 방식:
딥할인 구매기회 비중, 재계산) 5분위 교차표. 2,500가구.

> **Spearman ρ = 0.838 · 동일 분위 58.7% · ±1 분위 이내 93.8%**

정의가 전혀 다른 두 지표(로열티 할인 금액 vs 딥할인 이벤트 비중)가 같은 고객 축을 가리킨다.
→ 통합 보고서에서는 **고객 축 하나로 통일**하고, 이 표를 정의 강건성 증거로 첨부한다.

## 상충 정리 (팀 합의 문안)

1. **카테고리 판정**: "단일 관측 설계(딥할인)로는 FDR 보정 후 차별화 근거가 없다(장준한 0/83,
   전영찬 유의 6/71). 그러나 전단지 ITT 설계(남궁현종, BH-FDR 44/72 유의)와 하류 관계 지표가
   같은 방향을 가리키는 16개 카테고리는 실행 후보로 올린다."
2. **56일 잠식**: "잠식은 관측되더라도 당일 증가분의 ~7%로 작다. 구매기회 조건부 설계에서는
   −0.031개(t≈−2), 0구매 포함 기회 패널에서는 0과 구분 불가(t=0.16) — 분모가 달라 둘 다 참."
3. **고객 축**: 명칭을 하나로 통일(예: "할인 반응 성향"). 근거는 03 교차표.

## 처치 정의 대조 — 각자 코드에서 직접 확인 (2026-08-18)

정의는 통일되어 있지 않다. 아래는 추측이 아니라 **커밋된 코드에서 확인한 것**이다.

| | 남궁현종 | 장준한 | 전영찬 |
|---|---|---|---|
| 전단지 처치 | **광고 코드만** (A,C,D,F,H,L) | `mailer <> '0'` — **전체 코드** (쿠폰 J/P·무료 X/Z 포함) | `mailer != '0'` — **전체 코드** |
| 진열 동반 | **제외** (display=0 구매기회만) | 미통제 | 미통제 |
| 분석 단위 | 구매기회 (구매일 조건부) | **0구매 포함** 기회 패널 | 구매기회 (조건부) |
| 주 처치 성격 | 노출 ITT | 노출 ITT | **실현 딥할인** (+전단지 보조) |
| 확인 위치 | `남궁현종/sql/40_mailer_causal/q_causal_clean.sql` | `장준한/src/phase2_design/build_mailer_treatment.py:32` | `전영찬/sql/07_mailer_exposure.sql` |

**무해한(의도된) 차이**: 조건부 vs 0구매 포함 단위는 서로 다른 질문(내연 vs 외연 마진)에
답하는 것이고, 실현 딥할인 vs 노출은 PART A/B 구분으로 이미 역할이 나뉘어 있다.

**팀원 공유가 필요한 차이 2건** (남궁현종 데이터에서 실측된 편의 방향):

1. **무료 증정(X/Z) 코드 포함** — 무료로 주는 상품을 "판촉 효과" 처치에 넣으면 수량 효과가
   동어반복적으로 커진다 (X/Z는 140,276행).
2. **진열 동반 미통제** — 전단지 노출의 상당수가 매장 진열을 동반한다. 진열 제외 시
   SOFT DRINKS 효과가 +44.3% → +31.4%로 줄었다 (**29% 과대추정**).

두 요인 모두 **효과의 크기를 부풀릴 수 있으나 부호는 바꾸지 않았다** (정제 후에도 전부 양수 유지).
따라서 통합 서사는 안전하며, 발표에서는 "남궁현종 정의가 가장 보수적이고, 가장 엄격한
정의에서도 효과가 살아남는다"로 제시한다. 단, 세 사람의 효과 크기를 한 표에 나란히 놓을 때는
이 정의 차이를 각주로 달아야 한다.

**부수 확인**: 전영찬 정가 공식(`SALES_VALUE − RETAIL_DISC`)에는 `COUPON_MATCH_DISC`가
빠져 있다. 총액 기준 리테일러 할인의 0.5%라 결과에 실질 영향은 없다 — 각주감.
