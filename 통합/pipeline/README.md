# 통합 파이프라인 — 표준 정의로 전체 분석 재현

개인 폴더의 원 분석은 아카이브로 보존하고, 이 파이프라인은 **팀 표준 처치 정의**
([../처치정의_표준.md](../처치정의_표준.md)) 하나로 세 사람의 분석 전체를
`data/` 원본 CSV에서 재현한다. BigQuery 불필요 — 로컬 DuckDB로 완결된다.

```bash
pip install duckdb pandas numpy scipy
python 통합/pipeline/run_all.py              # 전체 (s1b 포함 시 수십 분)
python 통합/pipeline/run_all.py --skip s1b   # 시간통제 payback 제외 빠른 실행 (~10분)
```

## 스테이지

| 스테이지 | 재현 대상 (원 설계자) | 내용 |
|---|---|---|
| `s0_marts.py` | 공통 | 표준 마트: fct(정가·할인 분해) · causal/cat 플래그 · 구매기회 |
| `s1_incrementality.py` | 상류 (장준한) | trip×카테고리 0구매 포함 기회 패널 ITT, pair FE + 가구 클러스터 SE |
| `s1b_payback_m3.py` | 상류 (장준한) | 56일 payback, 시간통제(pair+WEEK+cat×월 FE 교대 사영) |
| `s2_allocation.py` | 배분 (남궁현종) | 72개 카테고리 판정(BH-FDR+유의 잠식) · 5분위 이질성 · halo · 지면 용량반응 |
| `s3_crm.py` | 하류 (전영찬) | 딥할인 vs 정가: 당일·사후 28/56일·체험 전환·28일 매장전체 하류 KPI |
| `s4_integrate.py` | 통합 | 삼각측량 · 의사결정 매트릭스 · 고객 축 교차표 (전부 이 파이프라인 산출물에서) |

각 스테이지는 **legacy 모드(원 정의)로 원 분석 수치를 먼저 재현해 구현이 옳음을 증명**한
뒤, standard 모드(표준 정의) 결과를 산출한다. 검증 로그는 `../outputs/s*_log.txt`.

## 표준 정의 전환의 실측 영향

- **s1 (기회 패널 ITT)**: 총수량 +33.7% → **+38.5%**. 효과가 커진다 — legacy 처치에
  쿠폰/무료만 걸린 셀이 "약한 노출"로 섞여 효과를 희석하고 있었다. 방향·유의성 불변.
- **s2 (카테고리 판정)**: 변화 없음 (원 분석이 이미 표준 정의).
- **s3 (딥할인)**: qty +0.416→+0.419, spend −0.320→−0.314 — COUPON_MATCH_DISC 포함
  효과는 미미. 정크 필터 확대 영향도 무시 가능.
- **s4 (고객 축)**: 할인의존도 × 할인친화도 Spearman 0.800, ±1분위 91.7% — 두 고객 축은
  사실상 하나라는 결론 유지.

## 개인 결과 결합판과의 관계

`통합/01~03_*.csv`(build_integration.py)는 **개인 폴더의 공표 결과를 그대로 이어붙인** 표이고,
`통합/outputs/s4_*.csv`는 **표준 정의로 전부 재계산한** 표다. 하류(28일) KPI 구현이
표준화되면서 일부 카테고리의 사분면·액션이 달라진다(예: BEEF). 차이는 오류가 아니라
anchor·비교 기준의 구현 차이이며, 제출물에는 s4(표준판)를 쓰고 결합판은 대조용으로 남긴다.
